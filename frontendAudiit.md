# Mobile Security, Privacy, Accessibility, and Reliability Audit

Audit date: 2026-10-23. Scope: checked-in Flutter client, Android/iOS project configuration, focused OpenAPI extracts, requested local build/test commands. Findings below are evidence-based; Play Console settings, production backend behavior, and physical-device behavior were not accessible.

## Findings

| ID | Area | Severity | Evidence | Impact | Fix | Status |
| --- | --- | --- | --- | --- | --- | --- |
| AUD-001 | Session privacy / medication reliability | P0 | `AuthController._endLocalSession` previously cleared tokens/chat only; medication queue is a single global secure-storage key (`lib/core/storage/storage_keys.dart:52-53`), and background handlers retain failed events for the next app open (`lib/features/medications/domain/medication_notification_handler.dart:17-22`). | Reminders could remain visible after sign-out, and pending intake actions could be replayed with a later account's token. | Session teardown now cancels app notifications and clears the pending medication queue before clearing tokens; regression test covers both. | DONE |

## Verified Controls

- Android APK metadata reports `targetSdkVersion='36'`; the manifest has backup disabled and extraction exclusions. Fine/background location and the geolocator streaming service are removed; no SMS, call-log, overlay, or Accessibility permission declaration was found in the app manifest. Exact alarms are declared for the explicit opt-in reminder setting.
- Merged debug APK permission output includes INTERNET, POST_NOTIFICATIONS, RECEIVE_BOOT_COMPLETED, SCHEDULE_EXACT_ALARM, WRITE_SETTINGS, READ_CONTACTS, SET_ALARM, RECORD_AUDIO, ACCESS_COARSE_LOCATION, VIBRATE, Play Billing, and ACCESS_NETWORK_STATE; no SMS/call-log, fine/background location, overlay, or accessibility permission appears.
- Release code permits cleartext only in `android/app/src/debug/AndroidManifest.xml`; production API defaults are HTTPS. iOS ATS allows local networking only, with no arbitrary-load exception observed in `Info.plist`.
- Android sensitive-screen protection wraps finance, medication, and logbook routes in `lib/router/app_router.dart`; the native bridge reference-counts `FLAG_SECURE` in `android/app/src/main/kotlin/br/com/novaiax/agente/MainActivity.kt`.
- AI device actions are parsed against an allowlist and the action flow checks server policy flags before execution (`lib/features/device_assistant/data/models/device_action.dart`, `lib/features/device_assistant/presentation/screens/device_assistant_screen.dart`). External URL parsing restricts scheme/host for supported backend-provided links (`lib/core/launch/safe_external_links.dart`).
- Billing displays the store-localized price and renewal/cancellation copy before purchase (`lib/features/billing/presentation/widgets/plan_card.dart`); the client completes a purchase only after backend verification (`lib/features/billing/presentation/providers/billing_providers.dart`). Pending purchases are not acknowledged.
- Medical reminders carry an informational disclaimer and explicitly tell users not to change treatment/dose (`lib/features/medications/domain/medication_reminder_planner.dart`). Finance surfaces show an app disclaimer. Community reports expose reporting/blocking flows in the feature; runtime permission disclosures are present for contacts and approximate location.
- The request/response logger is attached only when `Env.isDebug` (`lib/core/network/api_client.dart:18-32`). No WebView implementation was found under `lib/`.
- iOS target settings use bundle ID `br.com.novaiax.agente` and deployment target 15.0; `Info.plist` declares usage text for location, photo library, and contacts, and ATS has no arbitrary-load exception. iOS screenshot blocking is not implemented.
- User account deletion is available in-app and the OpenAPI `DELETE /api/v1/me` contract describes removal of owned rows and Redis keys; backend execution was not independently tested.

## Verification

- Baseline `flutter test`: passed before audit changes.
- Focused `test/privacy_account_deletion_test.dart`: 8 passed after deletion-wipe change.
- Focused `test/auth_controller_test.dart`: 16 passed after logout cleanup change.
- Final `flutter test`: 822 passed, 0 failed.
- `flutter analyze`: no errors; one pre-existing informational lint at `lib/shared/chat/chat_screen.dart:418`.
- Final `flutter build apk --debug`: passed; APK metadata confirms target SDK 36.
- `flutter build apk --release`: blocked by missing release signing configuration, as intended by the Gradle guard.
- `flutter pub outdated`: 46 locked packages have updates; `cupertino_ui 1.1.0` and `material_ui 1.3.0` are retracted.
- API path scan normalized path parameters and compared Dart client literals with OpenAPI keys. Only app-config, promotion listing, and promo redemption are missing; `/community`, `/me/finance`, and `/me/study` are client base prefixes, not endpoint mismatches.
- Contract verification was path-level only; exhaustive request/response field, enum, and error-code reconciliation across every endpoint remains open. Missing-route schema checks are recorded in `docs/BLOCKERS.md` and `docs/BACKEND_ISSUES.md`.
